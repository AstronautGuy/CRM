# Phase 6: Auth UI Forms & Middleware Redirect Protection

## Overview
Implement dedicated user interface pages for Authentication (Sign In and Registration) and configure Next.js Middleware to protect authenticated routes, ensuring users who are not logged in are redirected to the `/login` page and authenticated users cannot access `/login` or `/register`.

## 1. Authentication UI Pages
- **`/login` (Sign In Page):**
  - **Location**: `src/app/login/page.tsx`
  - **Features**:
    - Email/Password form using Shadcn UI `Form`, `Input`, `Button`.
    - Phone/Password form tab or option.
    - Social OAuth buttons (GitHub, Google) invoking `signIn(provider)`.
    - Client-side validation using `zod` and `react-hook-form`.
  
- **`/register` (Sign Up Page):**
  - **Location**: `src/app/register/page.tsx`
  - **Features**:
    - Registration form collecting Name, Email, Phone, Password, and Organization Name.
    - Uses tRPC to create the user and a new Organization tenant simultaneously.
    - After successful registration, redirects to login or automatically signs in.

## 2. Server & API Logic
- **Registration tRPC Endpoint**:
  - Add a procedure in a new router or the `admin`/root router to handle `registerUser`.
  - Hash passwords using `bcrypt` (or `argon2` if preferred) before storing in the database.
  - Create the `User`, `Organization`, and link them in `OrganizationMember` with `OWNER` role.

## 3. Middleware Route Protection
- **`middleware.ts`**:
  - **Location**: `src/middleware.ts`
  - **Features**:
    - Intercept requests using NextAuth v5 `auth` wrapper.
    - Define `protectedRoutes`: `/admin`, `/contacts`, `/pipeline`, `/billing`, `/products`, `/marketing`, `/tasks`.
    - Define `authRoutes`: `/login`, `/register`.
    - Redirect unauthenticated users hitting `protectedRoutes` to `/login`.
    - Redirect authenticated users hitting `authRoutes` to `/pipeline` or a main dashboard.

## Dependencies / Requirements
- Shadcn UI Form, Input, Button, Tabs, Card.
- `bcryptjs` or `bcrypt` for password hashing (needs to be installed and added to `package.json`).
- `zod` for form schemas.
- Ensure compatibility with existing `src/server/auth.ts` NextAuth credentials provider.

## Verification
- Navigating to `/contacts` without session redirects to `/login`.
- Submitting valid credentials on `/login` redirects to protected route.
- Submitting the `/register` form creates an organization, a user, and a member link in the database.
